# Week 03. 해외상품 전략 구현: MNQ 개장 전 범위 돌파

## 수행 내용

CME 마이크로 나스닥100 선물 2026년 12월물을 대상으로 미국 정규장 개장 전 1시간의 범위를 이용한 돌파 전략을 구현했습니다. 실시간 체결은 WebSocket으로 받고 주문은 REST API로 보냈습니다.

- 상품: Micro E-mini Nasdaq-100 202612 (`MNQZ26`), CME (`FCME`)
- 전략: 22:30 ~ 23:30 범위 돌파와 VWAP 방향 확인, 5분봉, 하루 1회
- 실행 환경: 모의계좌 주문
- 실행일: 2026-11-05
- 실행 결과: 매도 신호 1회, 손절 폭 한도 초과로 주문하지 않음
- 주문 확인: 같은 날 시운전에서 진입, STOP 접수 및 취소, 시간 청산 확인 ([6-3](#6-3-시험-주문과-시운전))

## 1. 과제 요약

- 시세 조회
  - 시작할 때 과거 분봉 REST 조회 (`core/market_data.py`)
  - 실행 중 WebSocket 체결로 5분봉 생성 (`stream.py`, `live.py`)
- 진입, 청산 (`strategy.py`, `live.py`)
  - 5분봉 종가가 개장 전 범위를 돌파하고 VWAP도 같은 방향일 때 진입
  - 손절, 익절, 23:55 시간 청산
- 위험 관리
  - 진입 직후 서버에 STOP 주문
  - 손절 폭이 400틱을 넘으면 당일 거래 중단
  - 하루 최대 1회, 1계약
- 실행 기록: `results/`에 실행 로그(`.log`)와 이벤트 기록(`.jsonl`) 저장
- 결과 분석: [백테스트](#6-1-백테스트), [모의계좌 실행 결과](#6-2-모의계좌-실행)

## 3. 전략과 매매 계획

### 3-1. 대상 상품

2주차에 거래한 3년 국채선물은 가격 움직임에 비해 비용의 영향이 컸습니다. 3주차 배정 상품인 MNQ와 MES 가운데 움직임이 더 큰 MNQ를 선택해 같은 문제가 줄어드는지 확인했습니다.

- 호가단위(1틱): 0.25포인트, 1계약 기준 $0.50
- 왕복 수수료: $4 (모의계좌 기간거래내역 기준, 건당 $2)
- 거래 시간: 미국 정규장은 서머타임 종료 후 23:30 KST 시작, 해외 모의계좌는 23:59까지 지원

### 3-2. 전략 근거

미국 정규장이 열리면 거래량이 늘어나므로, 개장 전에 만들어진 범위를 벗어나는 움직임이 이어질 수 있다고 봤습니다. 9월 22일부터 11월 4일까지 32일을 확인한 결과, 개장 후 20분의 봉당 거래량은 개장 전 1시간 평균의 약 7.2배였습니다(중앙값 기준).

처음에는 개장 후 15분 범위를 검토했지만, 모의계좌가 23:59에 끝나 실제 진입 기회가 한 번뿐이었습니다. 개장 전 1시간을 기준으로 삼아 개장 직후부터 판단할 수 있게 바꿨습니다.

2주차와 같은 추세추종 방식이지만 이동평균 교차 대신 시간대와 가격 범위를 사용했습니다. 짧은 등락에서 교차 신호가 반복되던 문제를 줄이기 위한 선택이었습니다.

### 3-3. 매매 규칙

- 범위: 22:30 ~ 23:30 5분봉 12개의 고가와 저가
- 진입
  - 매수: 5분봉 종가가 범위 고점과 VWAP보다 높을 때
  - 매도: 5분봉 종가가 범위 저점과 VWAP보다 낮을 때
  - 23:35, 23:40, 23:45, 23:50 봉 마감에 판단
  - 하루 최대 1회, 1계약
- VWAP: 겨울 기준 08:00부터 누적, 봉 대표 가격은 (고가 + 저가 + 종가) / 3
- 청산
  - 손절: 개장 전 범위의 중간값
  - 익절: 진입가에서 손절 폭의 2배
  - 본전 이동: 손절 폭만큼 유리하게 움직이면 손절 가격을 진입가로 변경
  - 23:55 시간 청산
- 한도: 신호 봉 종가부터 손절 가격까지 400틱(100포인트, 1계약 기준 $200)을 넘으면 당일 거래 중단

### 3-4. 주문 처리

- 시작할 때 포지션이나 미체결 주문이 남아 있으면 실행하지 않습니다.
- 진입은 시장가로 주문하고, 체결 직후 손절 STOP-M 주문을 냅니다.
- 익절과 시간 청산은 기존 STOP 주문의 취소를 확인한 뒤 시장가로 주문합니다.
  - STOP 주문이 남은 상태에서 청산하면 반대 포지션이 생길 수 있어 취소를 먼저 확인합니다.
  - 앞선 청산 주문이 처리 중이면 새 청산 주문을 내지 않습니다.
- 5분마다 현재가, 시세 시각, 포지션, REST 호출 수를 기록합니다. 포지션이 있으면 잔고와 손절 주문도 확인합니다.
- 23:57에 포지션과 미체결 주문을 다시 확인한 뒤 종료합니다.

### 3-5. 설정값을 정한 과정

비교 기간이 짧고 거래 수도 적어 최적값을 고르기보다, 미리 정한 기준값의 민감도를 확인했습니다. 버전별 결과는 [6-1 표](#6-1-백테스트)에 정리했습니다.

- 기본 전략에서는 이동평균을 빼고, SMA20 방향 조건을 추가한 버전을 따로 비교했습니다.
- 최대 손절 거리는 200틱, 300틱, 400틱을 비교했습니다.
- 비교 기간에는 200틱 버전의 수치가 가장 좋았지만 거래가 2건뿐이어서 선택 근거로 쓰지 않았습니다.
- 본 실행에는 사전에 정한 `base`의 400틱을 사용했습니다. 이 값은 최적값이 아니라 실행을 위한 임시 상한입니다.

## 4. 사용 API와 구조

### 4-1. 사용 API

| 구분 | API | 사용 방식 |
| --- | --- | --- |
| 인증 | `auth-service/v1/token` | 토큰 만료 5분 전 재발급 |
| | `permission/v1/web-socket-key` | WebSocket 접속 시 키 발급 |
| 시세 | `overseas/chart-minute` | 과거 분봉 조회, 첫 봉 마감과 재접속 후 분봉 갱신 |
| | WebSocket `FA` | 실행 중 실시간 체결 수신 |
| 주문 | `overseas/order` | 시장가, STOP-M, 취소 주문 |
| | WebSocket `O1` | 실행 중 주문 상태와 체결 수신 |
| | `overseas/order-history` | 체결 지연과 미체결 주문 확인 |
| 계좌 | `overseas/deposit` | 시작과 종료 시 예탁자산 확인 |
| | `overseas/open-interest` | 포지션 확인 |

본 실행의 REST 호출은 모두 10회였습니다. 2주차처럼 호가를 1초마다 REST로 조회하지 않고, 장중 시세는 WebSocket으로 받았습니다.

### 4-2. 구조

```text
core/                 모든 주차 공통
  config.py           .env, 설정 파일, 데이터 경로
  client.py           토큰, API 요청, WebSocket 키, 호출 횟수
  market_data.py      차트 조회
  bars.py             봉 데이터, CSV 저장
  indicators.py       SMA, ATR, VWAP
week03/
  config.json         종목, 전략, 버전, 실행 설정
  strategy.py         범위, 신호, 손절과 익절 가격, 진입 판단
  broker.py           해외 주문, 체결, 잔고
  stream.py           WebSocket 접속과 수신
  fetch_data.py       과거 분봉 저장
  backtest.py         설정 버전별 백테스트
  live.py             모의계좌 실행
  results/            실행 로그
  screenshots/        체결 내역, 잔고 캡처
```

백테스트와 장중 실행은 `strategy.py`의 같은 함수로 범위, 진입 신호, 손절가와 익절가를 계산합니다.

## 7. 결과 해석과 한계

### 7-1. 백테스트

**비교 기간에는 이익이었지만 확인 기간에는 손실로 바뀌었습니다.** 두 기간의 거래가 모두 11건이라 전략의 유효성이나 버전별 차이를 판단하기에는 부족합니다.

- 슬리피지 0틱과 1틱의 차이는 작았습니다. 2주차처럼 비용 때문에 손익 방향이 바뀌지는 않았습니다.
- 신호가 나온 19일 중 8일은 400틱 한도로 제외됐습니다. 범위의 절반이 100포인트 안에 들어도, 돌파 후 종가와 중간값의 거리는 더 커질 수 있었습니다.
- 비교 기간 6건 중 5건은 23:55에 시간 청산됐습니다. 보유 시간이 최대 25분이라 익절가에 도달하기 전에 끝나는 경우가 많았습니다.
- 백테스트에는 다음 가정을 적용했습니다.
  - 신호 다음 봉의 시가에 진입
  - 한 봉에서 손절과 익절에 모두 닿으면 손절로 계산
  - 본전 이동은 조건을 만족한 다음 봉부터 적용
  - 체결할 때마다 고정 슬리피지 적용

### 7-2. 모의 실행

**본 실행에서는 거래가 없어 전략 성과를 판단할 수 없습니다.** 대신 시세 수신, 5분봉 생성, 범위와 VWAP 계산, 위험 한도가 계획대로 동작하는지 확인했습니다.

- 범위 확정과 신호 판단 시각이 계획과 같았고, 손절 폭이 한도를 넘자 주문을 내지 않았습니다.
- 이날 범위의 절반은 87.5포인트였지만, 개장 첫 5분봉이 크게 하락해 신호 가격부터 중간값까지의 거리는 309.75포인트가 됐습니다.
- 23:55 가격은 27,563.00이어서 진입했다면 이익이었을 가능성이 큽니다. 다만 결과를 확인한 뒤의 해석이므로 규칙은 바꾸지 않았습니다.
- 시운전에서는 진입, STOP 접수와 취소, 시간 청산까지 확인했습니다. STOP 실제 체결, 익절, 본전 이동은 실제 주문으로 확인하지 못했습니다.
- 진입 주문은 WebSocket과 주문내역으로 체결을 확인하고, 확인이 늦으면 잔고를 10초 더 조회합니다. 이 시간 뒤에 체결되는 경우는 아직 처리하지 못합니다.

## 8. 오류 제보와 개선사항

- **제보 1: 실시간 구독 응답 필드가 명세 샘플과 다름**
  - 명세 샘플은 `rt_cd`에서 구독 결과를 확인하지만, 실제 응답은 성공과 실패 모두 `code`로 왔습니다.
  - 샘플대로 처리하면 구독 실패를 확인할 수 없어 `stream.py`에서는 두 필드를 모두 확인합니다.
  - 오류-문의 채널에 제보했으며 답변을 기다리고 있습니다.

- **제보 2: 해외 분봉 시각의 기준이 명세와 다름**
  - 분봉의 `occurs1_exch_tm`은 거래소시간으로 안내되어 있지만, CME, 홍콩, 싱가포르 종목에서 모두 한국 시간과 같은 값이 왔습니다.
  - 실시간 체결의 `exch_tm`은 거래소 현지 시간, `ko_exec_tm`은 한국 시간으로 구분되어 있어 분봉과 기준이 달랐습니다.
  - 현재 코드는 분봉 시각을 한국 시간으로 사용합니다.
  - 오류-문의 채널에 제보했으며, 담당자님의 답변으로 해외 분봉 시각은 거래소와 관계없이 한국 시간 기준임을 확인했습니다.

- **확인 사항: 분봉 거래량**
  - `cum_trd_qty`는 이름과 달리 봉마다 값이 오르내려 봉별 거래량으로 보고 VWAP에 그대로 사용했습니다.

## 9. 향후 계획

- 더 긴 기간으로 거래 수를 늘려 전략과 손절 한도 재검토
- 최대 손절 거리를 고정값이 아닌 범위 크기로 정하는 방식 비교
- 같은 MNQ 데이터에 2주차 이동평균 교차 전략과 개장 후 15분 범위 돌파 전략 적용

- 진입 체결 확인이 늦어질 때 주문 상태를 끝까지 추적하도록 보완
